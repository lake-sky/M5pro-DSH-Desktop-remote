# AI 工具赚钱项目集 (ai-money-projects)

本目录是**以 AI 工具为核心生产力、围绕「用 AI 赚钱」这一目标开展的所有实践项目的总集**。
每个子项目都按 **全流程** 记录：从机会发现、调研、立项、研发、运营、变现，到复盘与归档，全程留痕，方便日后复用方法论、对比 ROI、避免重复踩坑。

> 这里的「AI 工具」既包括使用第三方 AI（ChatGPT、Claude、Midjourney、Cursor 等）来创造产品或服务，也包括自己基于大模型开发并对外提供的工具型产品。

## 每个项目都需要记录什么

为保证「全流程运作情况」可追溯，每个项目目录**至少**包含以下文件（模板见 [00-templates/](00-templates/)）：

1. **`README.md`** —— 项目总览：定位、目标用户、价值主张、当前状态（想法/调研/开发/上线/运营/已归档）、关键链接。
2. **`01-discovery.md`** —— **机会发现**：怎么发现这个点子的？痛点来源、竞品观察、社区反馈。
3. **`02-research.md`** —— **调研**：目标人群、市场规模、竞品对比、定价参考、风险与门槛。
4. **`03-plan.md`** —— **计划**：MVP 范围、里程碑、技术选型、工具栈、预算与时间投入。
5. **`04-build.md`** —— **研发流水账**：按日期记录开发/创作进度、关键决策、踩坑与解决。
6. **`05-launch.md`** —— **上线/发布**：上线渠道、首批用户获取方法、上线 Checklist。
7. **`06-operate.md`** —— **运营与变现**：渠道数据、收入支出、用户反馈、迭代计划。
8. **`07-review.md`** —— **复盘**：项目结束时总结成功要素、可复用方法、失败教训、数据指标。
9. **`/assets`** —— 图片、截图、数据导出、合同、发票等原始资料（如需保留）。
10. **`/code`** 或 **`/content`** —— 项目本身的产物（代码/文案/课程包等），与「过程文档」分离。

> 命名编号保持两位数前缀，便于按时间顺序查阅；如需要更多阶段文件，可追加 `08-xxx.md`。

## 状态机

项目状态在 `README.md` 顶部以徽标形式维护：

| 状态 | 含义 |
| --- | --- |
| 💡 **idea** | 仅有想法，未开始调研 |
| 🔍 **research** | 正在做调研，未投入开发 |
| 🛠 **building** | 正在开发/创作 MVP |
| 🚀 **launched** | 已上线，正在运营 |
| 💰 **profitable** | 现金流为正 |
| 🧊 **on-hold** | 暂时搁置（保留位次与上下文） |
| ❌ **killed** | 主动放弃，记录原因 |
| 📦 **archived** | 跑通转交或完结，归档到 `99-archive/` |

> 状态变化时请同时在 `04-build.md` 或 `06-operate.md` 中记录触发原因与时间。

## 命名与版本控制规范

- 目录命名一律使用 **kebab-case 英文**（如 `youtube-shorts-factory`），与本工作区其他目录保持一致。
- 同一项目产生新阶段产物（如 v2、迁移到新平台）时，**优先在原项目目录下加 `v2/` 子目录**；只有当旧项目彻底废弃时才迁移到 `99-archive/`。
- 数字前缀（`01-` `02-` …）是**阶段文件**的固定编号；项目子目录不强制带数字，按业务命名。
- 所有项目级 README 必须包含：状态徽标、目标用户、价值主张、关键指标（北极星指标 + 1–2 个副指标）、最新更新时间。

## 方法论沉淀

跨项目总结出的可复用经验会抽取到上层 [`../skills/`](../skills/) 目录，形成可调用的 skill（如「冷启动一个 AI SaaS 的 7 步法」），再被本目录的新项目复用。
反过来，本目录中的项目过程文档（特别是 `07-review.md`）是 skill 的**素材来源**。
