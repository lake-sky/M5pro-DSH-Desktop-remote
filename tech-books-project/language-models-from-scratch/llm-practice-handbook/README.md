# llm-practice-handbook（大语言模型实操手册）

《从零到垂直：大语言模型实操手册》的编写区。

以**开源从零构建项目为起点**，把「训练 → 推理 → 使用」模型的全过程按实操步骤写出来，并把其间可能遇到的问题与解决办法逐条列出（**第一部分**）；再以此为基础，用一个**真实业务**走完专用垂直模型的构建（**第二部分**）。

## 定位

- **是操作手册，不是原理综述**：每一步都要能照着跑通、能复现、能排错。原理只写到「够用来做决策」为止。
- **从成熟开源项目起步，不重复造轮子**：以两个真正的从零实现作为并行参考主线——
  - [**MiniMind**](https://github.com/jingyaogong/minimind)（约 63k★）：约 64M 参数、约 2 小时、约 3 元成本，从 0 训练一个超小语言模型，面向**个人显卡**，体积约为 GPT-3 的 1/2700。
  - [**nanochat**](https://github.com/karpathy/nanochat)（约 58k★）："The best ChatGPT that $100 can buy"，覆盖 tokenization / 预训练 / 微调 / 评测 / 推理全阶段，单机 8×H100 约 2 小时（约 $48，spot 约 $15）训到 GPT-2 水平，整条模型系列靠一个 `--depth` 复杂度旋钮配置。
  - 两条主线恰好对应**小语言模型**与**大语言模型**两种算力预算：同一套流程走两遍，读者按自己的硬件选路。
- **排错是一等公民**：每章固定设「现象 → 原因 → 排查 → 解决 → 预防」栏，第一部分末尾再汇总成可按现象检索的排错手册。
- **落到真实业务**：第二部分不做玩具 demo，选一个具体业务，走完数据、适配、评测、上线与迭代的闭环。

## 全书结构

### 第一部分 · 跟着开源项目跑通全流程

同一套实操流程，在 MiniMind（小）与 nanochat（大）两条主线上各走一遍，逐阶段对照差异：

环境与跑通 → 数据与分词 → 预训练 → 监督微调 → 偏好对齐 → 评测 → 推理与部署 → 使用模型 → **排错手册**

### 第二部分 · 从通用到垂直（案例已定：小学语文教学辅导）

为小学生做语文学习辅导的**专有小语言模型**：纠正诗词易错字、讲解汉字结构与组成、笔画与笔顺、发音，可在本地（家用电脑 / 学校机房 / 低配服务器）离线运行。

业务定义与选型 → 领域数据治理 → 继续预训练/领域适配 → 领域 SFT 与对齐 → RAG 与工具（让事实可靠）→ 评测与上线 → 成本与迭代

> **为什么选它**：该领域有权威客观真值（笔顺国标、规范辞书），正误可判定；但容错率极低，教错笔顺会把孩子带偏，加上「无 GPU 服务器 + 未成年人数据」的硬约束——正好逼出「**小模型 + 权威知识库 + 工具调用**」这一核心工程结论。完整场景清单与理由见 [outline.md](outline.md) 第二部分。

## 目录规划

### 书稿目录

| 目录 | 放什么 |

### 章节与目录的对应关系

- 正文章节文件与 `outline.md` 的章号严格一一对应（`ch07-inference-deploy.md` ↔ 第 7 章）。
- 每章配套代码放 `code/chNN-主题/`，正文引用的命令一律指向该目录，保证「书里的命令可以直接复制执行」。
- 坑点既在章内出现，也汇总进第一部分末章（排错手册），两处共用同一编号（如 `P-042`）互相索引。

## 写作规范

1. **可复现优先**：命令、依赖版本、随机种子全部写清；引用开源项目时标注 commit 或版本，避免上游漂移导致读者跑不通。
2. **标注硬件成本**：每个实操环节标注最低显存/卡型、大致耗时与费用，让读者先判断自己能否跑。
3. **双线对照**：同一阶段先讲小模型路线（便宜、快、易调），再讲大模型路线（贵、慢、更接近工业流程），并用表格对比。
4. **坑点格式统一**：`P-编号｜现象｜可能原因｜排查步骤｜解决办法｜如何预防`。
5. **不贴大段源码**：代码放 `code/`，正文只给关键片段与调用方式。
6. **中文写作、术语中英并列**：首次出现的专业术语给出英文原词。
