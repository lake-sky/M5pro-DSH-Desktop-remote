## 第二部分 · 从通用到垂直（案例已定：小学语文教学辅导）

**案例**：为小学生提供语文学习辅导的**专有小语言模型**——帮助学生纠正诗词易错字、理解汉字结构与组成、掌握汉字笔画与笔顺、纠正发音，并可在本地（家用电脑 / 学校机房 / 低配服务器）离线运行。

**为什么这个案例适合做垂直小模型**：

- **有权威客观真值**：笔画与笔顺有国家标准（《通用规范汉字表》、笔顺规范），字音字义有权威辞书依据；正误可判定，评测不必依赖主观打分。
- **容错率极低**：教错笔顺、报错读音会把孩子带偏，所以「不许编」比「答得漂亮」重要——天然逼出「小模型 + 权威知识库 + 工具调用」的工程结论。
- **算力与隐私约束硬**：目标场景没有 GPU 服务器，数据又涉及未成年人，必须小模型、可量化、可离线。
- **场景边界清晰**：字、词、音、形四类，适合作为垂直模型的第一个落点。

**技术路线结论**（第 10 章展开论证）：小模型（继续预训练 + 轻量 SFT 学会「怎么说」）+ 权威结构化知识库与工具（保证「说得对」）+ 必要时 RAG（教材与教辅内容）。

### 第 10 章 业务定义与选型
- 场景清单与优先级：①诗词易错字纠正 ②汉字结构组成（偏旁部首 / 结构类型）③笔画与笔顺 ④拼音与多音字发音 ⑤字词解释与造句（后续扩展）
- 质量红线：客观题（笔画 / 笔顺 / 读音）必须准确；不会时必须说「不确定，请查字典」，不许编造
- 决策树落点：为什么不是「纯微调」，而是「小模型 + 知识库 / 工具 + RAG」
- 成本与 ROI：家用与校用设备的算力预算、可接受的响应时延
- 交付形态：离线可跑的问答助手（CLI / 网页 / 小程序后端）

### 第 11 章 领域数据治理
- 权威数据源梳理：通用规范汉字表、笔顺规范、字典释义、小学语文教材生字表、必背古诗词、学生真实错题
- 数据合规：未成年人数据脱敏、教材与辞书的版权边界
- 标注规范：错字—正字对、易错类型标签（形近 / 音近 / 多笔少笔 / 笔顺错）、难度分级
- 训练集与评测集隔离，防止评测集污染

### 第 12 章 继续预训练与领域适配
- 领域语料构造：教材文本、字词解释、诗词注释、教辅讲义
- 在 MiniMind 级小模型上做领域继续预训练的可行配置
- 保留通用能力：领域语料与通用语料的配比实验

### 第 13 章 领域 SFT 与对齐
- 指令集构造：纠错、解释结构、报笔画笔顺、报拼音、讲解诗词
- 结构化输出：用 JSON 输出「正字 / 错误类型 / 解释」，便于程序校验
- 拒答与兜底：不确定时转查字典或请老师确认
- 儿童场景的语言安全与措辞规范

### 第 14 章 RAG 与工具：让事实可靠
- 权威知识库落地：字典 / 笔顺 / 拼音数据如何结构化与检索
- 工具调用设计：模型只决定「查什么、怎么讲」，事实由工具返回
- 对比实验：同一批客观题上，纯微调 vs 工具增强的正确率差异
- 知识更新：教材改版或辞书修订时，只更新知识库而不必重训模型

### 第 15 章 评测、上线与迭代
- 评测集设计：字 / 音 / 形分场景；客观题准确率与讲解质量双轨评测
- 上线形态：家庭电脑、学校机房、离线平板
- 学生错题回流与再训练的触发条件
- 版本与灰度：教材版本、地区差异

### 第 16 章 工程化与成本
- 量化与端侧部署：4-bit / 8-bit、CPU 推理速度与体验取舍
- 响应时延目标与缓存策略
- 维护成本与更新节奏
